## 0. 一句话结论

- **拆解对象定台式机 · ATX 海景房（三面玻璃）**。不是因为「电脑拆得多、模型多」这两条（对当前零 GLB 管线无效），而是因为**现有文案与 A4 痛点幕只在台式机上成立**（详见 §2）。手机方案要重写全篇文案，收益不抵成本。

## 2. 选型：为什么是台式机（含反方论证）

### 2.1 常见选型理由逐条核对：只有一条真正成立

- 「电脑拆得多」→ **不构成理由**。拆解视频多不多只影响参考素材，不影响我们画什么——我们不用参考视频的像素，只取几何与时长。
- 「差异小、架构成熟」→ **成立但次要**。零件语言稳定，意味着几何表一次定、复用久。
- 「模型多、能拍照建模」→ **对当前管线无效**，见 §2.5。
- 「手机东西小、难拍」→ **方向对，但真实原因不是"难拍"**，是下面三条。

### 2.2 三条硬理由（按权重排序）

**① 文案已经锁死设备，换手机 = 全篇重写。**
v1.0 的 A2 / A3 / A5 要点里出现的是：`B760 和 Z790 你该为哪个多付钱`、`电源瓦数怎么算，才不会点不亮`、`工具、防静电、走线，全都教`、`每学期一次整机装配，从零到点亮`。
这四句是桌面 DIY 独有词汇。手机没有「芯片组差价」、没有「电源瓦数」、没有「走线」。手机拆解讲的逻辑是另一套（集成度、维修性、保修条款），**不是换名词能迁移的**。

**② A4 痛点幕只在台式机上站得住 —— 这是全片情绪最高点。**
v1.0 A4 要求：镜头钻进内存条与固态之间，这两个零件保持高亮 + 暖色。
台式机上，内存条是**能用手捏出来、能单独买、能指着说"这条涨了多少"**的独立零件；M.2 固态同理。手机里的 DRAM 与闪存是 BGA 焊死在主板上的芯片，肉眼看不出"这是内存"，观众也无法把"这块钱可以等"落到具体物件上。
存储涨价这件事，台式机让它**可见**，手机让它**不可见**。参考：[2026 年 DDR5 涨价三倍](https://ai.zol.com.cn/1112/11129135.html)。

**③ 手机比台式机更难做得像。**
手机内部是层叠 + 排线 + 屏蔽罩 + 异形小板，零件碎、遮挡多，用几何基元拼出来的剪影辨识度低——观众认不出哪块是什么，冲击力反而下降。台式机零件几乎全是长方体 / 圆柱 / 圆环，散开就能读懂。对「没见过这种东西」这个目标，**剪影可读性 > 细节真实度**。

### 2.3 反方（手机方案的真实优势，不回避）

- **代入感**：手机是每个观众兜里都有的东西，"你手上这台"比"某台机箱"更近。
- **素材量**：iFixit 等拆机图解极丰富，参考成本低。
- **形态差异小**：手机之间差异小于台式机（台式机有 ITX/中塔/全塔/海景房）。

但招新受众是新生，**"装机文化"本身就是社团卖点**（社团做装机、帮人选购），代入感的收益小于叙事完整性。→ **维持台式机**。

### 2.4 已定：ATX 海景房（三面玻璃）与它的适配代价

| 部位 | 选型 | 由选型带来的改动 |
|---|---|---|
| 机箱形态 | **ATX 海景房 · 三面玻璃**（前 + 右玻璃 + 顶部网孔盖） | A0 的「看不清内部」改由**玻璃镜面反射**承担；A1 的"打开"改为**反射褪去 + 内部点亮**（不是拆侧板） |
| 结构 | 双仓（主仓 + 电源仓，中间隔板） | 零件表新增「仓隔板」，A2 电源从下仓飞出 |
| 框架 | 4 立柱 + 4 横梁，玻璃挂在框架上 | **三面通透后剪影变弱 → 框架梁线宽 ≥1.6px，且只改透明度不动位**；验收新增「缩到 320px 仍认得出是机箱」 |
| 进风 | **底部进风 ×3** | 海景房前面板全玻璃，没有前面板进风位（v0.1 的「进风 ×3」无处安放） |
| 玻璃在镜头里的处理 | A2 退场后留 **0.10 残影**，A4 段归零，A5 回升 | 归零会让观众忘记这是玻璃柜；但贴脸幕必须归零，否则穿模 |
| 主板 / 散热 / 内存 / 显卡 / 电源 / 存储 | B760 · 塔散（非水冷）· 双条 DDR5 · 单双槽卡 · ATX 3.1（12V-2x6）· 主板面 M.2 带散热片 | 塔散优于水冷：软管爆炸方向不好定义、几何更容易看假；电源是 **3.1 不是 3.0**（2024 年起 12VHPWR 已被 12V-2x6 取代，[12VHPWR](https://en.wikipedia.org/wiki/12VHPWR)、[ATX3.1 解读](https://zhuanlan.zhihu.com/p/1995653156596643403)） |

### 2.5 明确不做：拍照建模

当前管线是**零 GLB、程序化几何**（工作区 AGENTS.md 红线：素材全本地；首屏预算 ≤ 800 KB）。走"拍实物 → 摄影测量 → GLB → draco 压缩"是另一条管线，工作量至少 3～5 倍，且本机 Arc B390 集显渲染本来就慢。
照片唯一的真实价值是**比例校准**，用厂商公布的三维尺寸参数即可替代。→ **不拍。**
以后若要按真机型号精确建模，那是 `motions/` 里新建条目的工作，不是这个站的前置条件。
