# 渲染管线

> **状态声明**：本节描述的是计划采用的路线，其中命令、退出码与参数按上游文档整理，**尚未在本机逐一实测**。实际已跑通的是手工链路：无头 Edge 截帧 + `@ffmpeg-installer/win32-x64` 编码，见 `recipes/scroll-teardown-headless.md`。

本机渲染器：**Multiplane**（`LBEILC/Multiplane`，Apache-2.0）。镜头就是普通网页，页面实现 `render(t)`，画面只由时间决定；它用无头 Chromium 逐帧截图、做超采样与运动模糊、用 ffmpeg 合成视频。

## 固定五步

```sh
# 1 静态检查：不开浏览器，一秒内出结果，定位到行列
npx multiplane lint <shot> --json

# 2 抽帧目视：关键帧各出一张 PNG
npx multiplane stills <shot> --at 0,1,2.5 --json

# 3 确定性检查：乱序、重载、单/多进程分别渲染同一批帧逐像素比对
npx multiplane verify <shot> --json

# 4 渲染成片
npx multiplane render <shot> --json

# 5 读结果：最后一行一定是 type=result
```

## 硬规则

1. **`verify` 不通过就不要渲染。** 失败码是 `nondeterministic_output`，看 `finding` 里的 `t`、变化像素数、`bbox` 和差异图定位。
2. **`gpu_raster_jitter` 警告不算失败**：集显光栅会让零星像素差一两级，肉眼不可见。要绝对一致就加 `--raster software`。
3. **渲染跑后台 job**，不给同步超时。中断后**不要重跑**，用：
   ```sh
   npx multiplane status <jobId> --json
   npx multiplane resume <jobId> --json
   ```
   已编码的分段（约 10 秒一段）会被复用，成片与一次渲完逐帧相同。
4. **退出码**：0 成功；1 镜头或检查不通过；2 参数错；3 环境问题（先跑 `doctor`）；4 渲染器内部错（重试一次）；130 被取消。
5. **不要解析 `message` 做判断**，用 `code`。

## 迭代与终稿的参数

| 阶段 | 参数 | 理由 |
|---|---|---|
| 迭代 | `--draft` | 以不超过 0.5 倍截图再放大，不做运动模糊与颗粒，快很多 |
| 迭代 | `--quality fast` | 与 standard 只差采样上限 |
| 终稿 | 默认 `standard` | 真实镜头上已足够 |
| 静帧交付 | `--quality high --scale 2` | 只在要放大看细节时用 |

**不要把 `--draft` 的产物当最终结果交付**（`result.data.draft` 为 true 就是草稿）。

## 本机性能现实

GPU 是 **Intel Arc B390 集显，无 CUDA**，只有 QSV 硬编。含义：

- 1080p 尚可，**4K 要按几十分钟一次规划**（参考量级：pdoom-video 的 4K 全曲在 M5 Pro 上约 57 分钟）。
- 并发进程数先跑一次 `npx multiplane benchmark` 实测，别照搬教程。三维镜头一律不超过 4 个进程——多个 WebGL 进程抢同一块集显只会更慢。
- 编码器用默认 `x264`；想试硬编可加 `--encoder` 指 QSV 构建，但**必须先 `doctor` 确认可用**。
