# 验收标准

网页与视频的验收**必须分开**——两者失败模式不同，混用会互相伤害。资产条目另有第三条线。

---

## 一、网页验收

### 底线（不可让的）

| 指标 | 门槛 | 说明 |
|---|---|---|
| LCP | ≤ 2.5 s | p75 |
| INP | ≤ 200 ms | p75 |
| CLS | ≤ 0.1 | p75 |

### 动效手感（CWV 管不到的）

| 指标 | 门槛 |
|---|---|
| 稳态帧率 | 桌面 ≥ 50 fps，移动 ≥ 30 fps |
| 1% low 帧率 | 不低于均值的一半 |
| 首帧时间（画布首个非空帧） | ≤ 2 s，在此之前必须有占位 |
| WebGL context lost | 必须为 0 次 |
| draw call | ≤ 150 |
| 三角形数 | ≤ 50 万 |

**注意**：INP 与帧率不可互相替代。INP 量的是交互响应，卡在 `rAF` 里的长任务只伤帧率。

### 体积预算

| 项 | 预算 |
|---|---|
| 首屏 3D 传输量 | ≤ 5 MB（Draco + KTX2） |
| 单个 GLB | ≤ 10 MB |
| 纹理边长 | ≤ 2048 |

### 自动化

- **Lighthouse CI** 适合卡体积、LCP、CLS。
- **不要用 Lighthouse 卡 FPS**——它在模拟 CPU 下跑，WebGL 结果不稳定。
- 要卡 3D 指标就自建探针：在 Playwright 里 `page.evaluate` 读 `renderer.info.render`（calls / triangles），并采集 `rAF` 时间戳算帧时间分布。
- 视觉回归用 Playwright 的 `toHaveScreenshot()` 时必须先消除时间不确定性：固定时钟、固定随机种子、固定相机矩阵。否则永远 flaky。

## 二、视频验收

按顺序，前一步不过不进下一步。

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | `multiplane lint` | 无 `severity: error` |
| 2 | `multiplane verify` | `ok: true`；`gpu_raster_jitter` 警告可忽略 |
| 3 | `multiplane stills --at <关键帧>` | 抽帧目视符合 `SPEC.md` 的观测量表 |
| 4 | `multiplane inspect --json` | duration / fps / 舞台尺寸符合预期 |
| 5 | 成片 | 帧数、时长、分辨率与预期一致（`result.data.outputCheck` 已自带） |
| 6 | 内容抽查 | 正式交付前抽查 20 帧以上，修掉拥挤、重叠、看不清 |

**"渲染成功"不等于"验收通过"。** 报告时必须分开说。

### 成本也要记

每条成片在 `video/<项目>/meta.json` 里记 `renders[]`：轮次、耗时、token 或美元、人审结论。

理由：这类工作的主要风险不是渲染失败，而是**轮次与成本失控**。参考量级——一句话短片约 2 美元/分钟；5 分钟 MV 单次会话可到 200 美元。

## 三、资产条目验收

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 目录完整 | `intent.json`、`SPEC.md`、`SOURCE.md` 齐全 |
| 2 | schema 合法 | 能对上 `motions/schemas/shot-intent.schema.json` |
| 3 | 三问通过 | `intent.json` 每个字段都过：换 fps？换画幅？换渲染器？ |
| 4 | 实现可跑 | `status: ready` 必须有 `ref/` 且过了 lint + verify |
| 5 | 索引同步 | `motions/library.json` 里有对应条目 |
| 6 | 来源清楚 | `SOURCE.md` 填全，`redistribute` 明确 |

## 四、容差（参考视频反向实现时）

有参考视频时不可能逐像素对齐，必须放宽，并写进 `intent.json` 的 `tolerance`：

| 项 | 建议容差 | 理由 |
|---|---|---|
| 几何位置 | ±1.5% 舞台宽高 | 视频压缩与缩放的固有误差 |
| 时刻 | ±2 帧 | 帧率对齐误差 |
| 不透明度 | ±0.05 | 编码会吃动态范围 |

**不可要求的**：压缩噪声、抗锯齿细节、平台水印与角标。
