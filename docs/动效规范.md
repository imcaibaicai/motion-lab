# 动效规范

本文件定义"手感"的唯一真源：缓动与时长。**网页与视频必须吃同一张表**，否则两边手感会慢慢漂移——这是整个工作区为什么要合并的硬理由。

真源文件在 `packages/motion`，本文件只解释取舍。

---

## 一、缓动族：只给族名，不给数值

**不要**在文档里写 `cubic-bezier(0.2, 0.8, 0.2, 1)`。具体数值属于实现细节，写死就等于锁死视觉，而且换技术栈就失效。

| 族名 | 感觉 | 典型用途 |
|---|---|---|
| `snappy` | 快进慢出，收得干脆 | UI 反馈、切换、点击响应 |
| `smooth` | 对称缓入缓出 | 位移、淡入淡出、镜头推拉 |
| `elastic` | 过冲回弹 | 强调、 playful 元素（**慎用**，易廉价） |
| `mask` | 遮罩式揭示，非位移 | 文字与图像入场 |
| `linear` | 匀速 | 进度、循环、时间轴指示 |
| `none` | 无过渡，离散切换 | 像素级重绘、步骤播放器 |

**判据**：写进文档的只能是族名。族名到具体曲线的映射在各端实现里，允许微调。

## 二、时长：用比例，不用帧数

- **视频**：用"占全片时长的比例"（`entryRatio: 0.08`），不用帧号。理由：24 fps 与 60 fps 下同一帧数是完全不同的时长。
- **网页**：用毫秒，因为网页没有"全片"这个概念。

## 三、错峰

多元素入场必须有错峰，否则观感是"整块出现"，廉价。

- 用 `index * staggerRatio` 的**闭式表达**，**禁止**用全局累加计数器。
- 原因：渲染器会乱序、多进程、重载页面；累加器在这些情况下会错位，`verify` 的 `workers` 项会直接失败。

## 四、离散 vs 连续

- **离散切换**（`none`）：每帧只有开/关两种状态。天然确定性，适合像素级重绘、步骤播放器、赛璐珞风格。
- **连续插值**：位置/透明度按 t 插值。必须写成 t 的闭式函数。

想让"按二拍"的效果（角色 12 fps 步进、镜头与光线保持每帧平滑），就**分别处理**：角色用 `floor(t * 12)` 量化，镜头用连续插值。混在一起会像卡顿。

## 五、模拟类效果的红线

弹簧、粒子、逐帧积分这类东西**不允许直接写在 `render(t)` 里**。

必须：在 `setup()` 里按固定步长把整个模拟预算成表 → `render(t)` 只查表。

含义（要如实告诉用户）：这类效果 `determinism.kind` 是 `precomputed-simulation`，**跨栈时要为每个效果多做一道预算工作**，成本高一档。

## 六、三维

- 三维**只是点缀**。统计上大部分好看的效果并不需要三维。
- 用到时优先"现成模型 + 镜头运动 + 光影"，不要一步跳到自写 shader。
- 自写 shader 属于后期滤镜层级，留到最后再加。

## 七、禁止清单

| 禁止 | 原因 |
|---|---|
| CSS `transition` / `animation` / `@keyframes` | 墙钟驱动，渲染不可复现 |
| `Date.now()` / `performance.now()` 影响画面 | 同上 |
| 未设种子的 `Math.random()` | 每次不同 |
| 远程字体 / CDN / 远程图 | 加载时序不可控，且破坏离线复现 |
| 全局累加器做错峰 | 乱序/多进程下错位 |
| 视频里用 GIF 交付 | 体积与画质都劣于 H.264 + `faststart` |
