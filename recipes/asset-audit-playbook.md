# 第三方素材包盘点：分档判据与隐蔽陷阱

适用场景：手上拿到一批现成的技能包 / 模板 / 组件库 / 设计系统资产（几十到几百个条目），要在半天内判断「哪些能直接进项目、哪些只能取数值、哪些是坑」，并留下可复查的结论。

> 本文件是**方法论**，不含具体第三方的文件清单与源码摘录。原始盘点记录留在本地私有目录，不随仓库分发；理由见 `AGENTS.md` 红线第 4 条与第 5 条。

## 一、先定五档，再逐条归档

没有分档的盘点会退化成一堆「看起来都还行」的描述。五档的判据是**改动量**，不是喜好：

| 档 | 判据 | 处理 |
|---|---|---|
| A | 零改造可用：纯函数、无外部依赖、无时间无状态 | 直接移植，补上被漏注册的条目 |
| B | 数值可采、方法可采：有 concrete 数值（毫秒、比例、字号、对比度）但作者没给口径 | 数值进 `packages/tokens`，口径写进 `recipes/` |
| C | 有用但必须改造：结构可借、执行流程不可借 | 只借骨架，实现重写 |
| D | 对「上下文工程 / 工具链」有参考，对画面无用 | 单独归档，不进交付物 |
| E | 不值得动 | 记一行理由就停，不要展开 |

**关键纪律**：E 档必须写理由。「不好」不是理由，「它的 scheme 让对比度落到 3.4:1，低于它自己引用的 4.5:1，文件内部自相矛盾」才是。

## 二、防漏筛：关键词正则先过一遍

几百个条目不可能逐个人读。先用**宽正则**把候选从全量压到可读规模，再分组只读深读：

```
design|anim|motion|video|visual|css|svg|canvas|font|image|render|ui|ux|artifact|icon|theme|brand|chart|gif|3d|web
```

深读时**每组限定工具调用次数（≤7 次）且零写入**，否则一次盘点会把自己的上下文吃光。每组的产物是「条目 → 档位 → 一句话判据」，不是读后感。

## 三、五个隐蔽陷阱（这部分比清单本身值钱）

### 3.1 远程资产遍地，且都藏在「最佳实践」的壳里

模板类资产的通病：`fonts.googleapis.com` 双 preconnect、`cdn.tailwindcss.com`、`cdnjs` 的 p5.min.js、字体配对表全部以 CDN 外链给出。

对**素材必须全本地**的项目来说，这些文件的可执行价值是**当 lint 的反面样本**，不是当模板。判断某个包能不能用，第一件事是 grep 它的 `http`。

### 3.2 确定性被「正确解法」包装着埋雷

最典型的形态：**代码层干净，文档层是重灾区**。代码里的缓动函数是纯函数，但 SKILL/README 里明文推荐「加一点随机变化更自然」「每帧按重力增加速度」。

结论：**抄代码可以，抄配方必踩红线**。逐帧积分状态累加、无种子随机，在网页里是「自然」，在逐帧渲染里是不确定源。

### 3.3 两个文档从不写、但会静默出错的点

1. **`prefers-reduced-motion` 在无头截帧里是不确定源**。媒体查询是否匹配取决于浏览器版本与 emulate 设置，不显式固定取值，同一个 URL 两次渲染可能出不同帧，`verify` 会偶发失败。CSS 过渡方案只能限定在「交互态」页面，**绝不能进 `render(t)`**。
2. **`font-weight` 过渡会改动行盒**。`500 → 600` 带 transition 会让文本 reflow，逐帧几何漂移，几何断言**假失败**。渲染态必须每帧直接给定最终 weight。

### 3.4 「去重减体积」的经典错法

现成的 GIF/序列帧构建器里常见：去重时直接删帧，但每帧时长仍然恒定为 `1000 / fps`。**删帧等于播放加速**，而 `duration_seconds = 帧数 / fps` 跟着一起错，且错得很自洽，肉眼要看到画面变快才发现。

自己做去重必须写 **per-frame duration**，并断言 `Σduration == frameCount / fps`。

### 3.5 反模式清单被绝对化会误伤

「禁大圆角」「禁 blob 形状」在 kawaii / 软性美学下是正当选择。把清单直接变成 lint `error` 会逼着人绕规则。

正确做法是**分级**：默认禁，例外必须在 `SOURCE.md` 记理由。lint 只对「无理由的默认使用」报错。

## 四、可机械解析 vs 不可解析，要先判

同一批资产里，能进脚本的和只能人读的必须分开，否则会写出一个跑一半就 `None` 的转换器。判据：

- **可机械解析**：定长列、纯 hex、纯数字、无散文夹带。一条脚本能转 JSON。
- **不可解析**：列数不一致（尾部字段缺失）、数值埋在散文里、单位混用。转出来是垃圾，只能人读后手抄。
- 参考思路：**按域分表 + 字段级检索**（自带 BM25 之类）比一张大表好用得多。
- 陷阱：检索脚本里常见的「把每个字段截断到 300 字」是**喂模型的瘦身视图**，不是数据导出通道。直接拿它当数据源会丢内容。

## 五、落地纪律

1. **只重写值，不拷贝文件**。数值抄进 `packages/tokens` 并在 `SOURCE.md` 记出处（文件 + 行号）。
2. **未读过的文件必须列「未覆盖清单」**，并标明哪些结论是推断而非实测。这是盘点文件可信度的来源。
3. **每档给出量级估算**，否则结论没法排优先级：半天 / 一天 / 需真跑实测。
4. 会改全局环境的脚本（`npm install -g`、写 `~/.config`）一律不执行，只读它的结构。

## 六、这次盘点得到的可复用结论

- 缓动函数表、单帧绘制原语（每帧新建画布、函数只吃参数不吃历史）是**最值钱的两类资产**，因为它们天然满足 `render(t)` 纪律。
- 设计数值（字号层级比、对比度、间距刻度、字体族上限、配色比、动效时长上限）可以直接进 tokens，但要先统一口径。
- 设计禁令表可以被改造成 lint 规则，前提是分级而非绝对化（见 3.5）。
- 「按触发条件写描述、不概括流程」这类**元层面的写法纪律**，价值高于任何具体效果实现。
